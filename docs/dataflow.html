Agent Egress Data Flow

How a request from the agent container reaches the network, or doesn't. Every path out goes through the proxy, which decides on the destination, the action and the content, then logs one line per flow.

One request, in order

  1. A tool in the container opens CONNECT host:443 to the proxy, because HTTPS_PROXY points there and nothing else routes out.
  2. The proxy refuses the tunnel if no rule lists the destination.
  3. It terminates TLS with a certificate the container trusts, then reads the method, path, headers and body.
  4. The rule checks the action: a method, a write to your own GitHub repo, an allowed MCP tool.
  5. Detectors scan for fronting, secret-shaped strings, high-entropy URLs and the broker placeholder.
  6. If allowed, the broker swaps the placeholder for the real token, and the request goes out over a fresh TLS connection.
  7. On the way back, an echoed token is replaced, and an MCP tool list is cut down to allowed tools.

What never leaves where it is

  • Request bodies are scanned in memory and never logged.
  • Model traffic to api.anthropic.com is not scanned; only host, method and path are logged.
  • The root CA key stays in ~/.agent-egress-ca. The proxy gets the intermediate; the container trusts the root certificate.
  • The real GitHub token is a file only the proxy mounts. The agent holds a placeholder.
  • Your Mac's traffic doesn't touch the proxy. It only serves the containers.
